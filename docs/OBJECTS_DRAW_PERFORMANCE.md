# Objects draw / grouping の高速化

## 変更

- Costume: 同じコスチュームが既に有効なら `setCostume` による状態の初期化を省略する。text/video から戻る場合は通常どおり切り替える。
- Text: 文字列とフォントごとに不変のGPUスキンを共有し、切り替え時の再アップロードを省く。ターゲット固有の動画・モデル用スキンと所有権を分ける。キャッシュは1024件・16Mピクセルを目安に削減し、表示中のスキンは保護する。既存の高解像度文字描画を維持する。
- Video: 同じターゲットのキュー内で連続する同一フレームは、デコード・画像コピー・GPUアップロードを1回にする。Objects scene 内では同一動画フレームの平面・テクスチャを共有する。各drawのスタンプは省略しない。
- Objects scene: 同じジオメトリ・マテリアルの連続する画像平面をインスタンシングする。反転・ゼロスケールの平面は従来の経路を使う。通常のPen描画を3D描画へ変更しない。
- Grouping: 隔離描画用テクスチャとフレームバッファーを再利用する。待機中の領域は最大8個・合計16Mピクセルまで。通常合成・不透明度100%ではGPUのsource-overブレンドを使い、合成を2パスから1パスに減らす。特殊ブレンド、グループ不透明度、expanded効果、名前付きパスの分離は保持する。
- グループ座標変換の三角関数を再利用し、回転値が変更されたときだけ再計算する。非同期資源の準備後に続く同期ノードを、ノードごとのマイクロタスクに分けずに実行する。

ブロックに待機・タイマー・VMへの新しいPromise返却を追加していない。グループ処理中は完成済みのPen画像を維持する。

## 実GPU測定

2026-09-09、ローカルChromium / WebGLで測定。出力960×720。
GPU完了待ちの `gl.finish()` はベンチマーク側だけで使用し、製品コードには追加していない。

| 条件 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 同一画像平面1000枚の3Dシーン、描画中央値 | 3.2ms | 1.8ms |
| 同シーンのGPU draw call（深度・色を含む） | 2001 | 3 |
| 同シーンのp95 | 3.8ms | 4.0ms |
| 全画面グループ1000個を順次合成、中央値 | 691.5ms | 311.4ms |
| 同グループ測定のGPU draw call | 2000 | 1000 |
| 同グループ測定のテクスチャ新規確保（ウォームアップ後） | 1000 | 0 |

3Dシーンは5回のウォームアップ後30フレーム、グループは1回のウォームアップ後5回を測定。3Dシーンの比較はインスタンシングを無効化した同一コード、グループの比較は変更前のHEAD版エンジンを使用。
3DシーンのRGBA全チャンネルは一致。グループ測定では均一色の最終ピクセルが一致し、WebGLエラーは0。

これは共有画像平面と通常合成の測定であり、異なる動画1000本の同時デコードや、1000個の独立した重いエフェクトの60fpsを保証するものではない。全画面グループ1000個の合成は改善後も1フレーム16.7msを超える。元の動画の解像度・フレーム時刻の違い、テキスト種類数、キャッシュ容量、重なり面積、エフェクトによって負荷は変わる。
